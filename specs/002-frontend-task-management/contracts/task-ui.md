# 契約: タスク管理 UI

## 目的

SCRUM-7 のフロントエンド画面が満たすべき UI 操作契約を定義する。

## 基本レイアウト

- 主画面はタスク一覧である。
- 画面上部または一覧近くに現在の userId を確認・切り替えできる入力を置く。
- 新規登録、詳細、編集、削除確認は TaskOverlay として開く。
- デスクトップ幅では TaskOverlay を右ドロワーとして表示し、一覧は背面に残す。
- スマホ幅では TaskOverlay を全画面モーダルとして表示する。

## 一覧

- 現在の userId に紐づく未削除タスクのみを表示する。
- 各行または項目には、タイトルと status badge を表示する。
- status badge は `TODO`, `DOING`, `DONE` を区別できる。
- タスクが0件の場合は、空の一覧であることと登録導線を表示する。

## 新規登録

- 一覧画面の新規登録操作から TaskOverlay を開く。
- 入力項目はタイトル、説明、ステータスのみ。
- タイトルとステータスは必須。
- 登録成功後は TaskOverlay を閉じ、一覧に登録結果を反映する。

## 詳細

- 一覧のタスクを選択すると TaskOverlay で詳細を表示する。
- 詳細にはタイトル、説明、ステータスを表示する。
- 詳細から編集と削除確認へ進める。

## 編集

- 詳細表示から編集モードへ切り替える。
- 入力項目はタイトル、説明、ステータスのみ。
- 保存成功後は詳細表示と一覧へ更新内容を反映する。

## 削除確認

- 削除前に確認を求める。
- 確認した場合のみ backend の論理削除 API を呼び出す。
- キャンセルした場合は削除せず、詳細表示または一覧へ戻る。

## フィードバック

- 一覧取得、登録、更新、削除の処理中は loading 状態を表示する。
- 登録、更新、削除の成功時は成功通知を表示する。
- API エラー時はユーザー向けメッセージを表示する。
- `ErrorResponse.details` がある場合は該当入力欄に表示する。

## レスポンシブ受け入れ条件

- デスクトップ確認では、一覧を見たまま右ドロワーを開閉できる。
- スマホ確認では、全画面モーダルで新規登録、詳細、編集、削除確認を完了できる。
- どちらの画面幅でも、未保存の TaskOverlay を閉じた場合は保存されない。
